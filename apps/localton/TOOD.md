# Localton TODO

## Исключить гонку `seqno` между участием в выборах и возвратом стейка

После отключения валидации на `genesis` сеть продолжила выпускать блоки силами `node2`, но следующий validator set не сформировался:

- `genesis` корректно вышел из активных validator groups (`master:0`, `shard:0`)
- `node2` остался единственным активным валидатором (`master:1`, `shard:1`)
- текущий validator set истёк, но `config 36` остался пустым
- `participant_list_extended` в Elector вернул нулевой стейк и пустой список участников
- runtime при этом сохранил выборы как успешно отправленные

Причина: `agent_auto_tick` в одном тике отправляет election entry, а затем сразу вызывает возврат старого стейка. Первая транзакция ещё не успевает попасть в блок, поэтому обе операции могут использовать одинаковый wallet `seqno`. В наблюдаемом случае в блок попал `recover-stake`, election entry потерялся, а локальный runtime заблокировал повторную отправку как уже выполненную.

Нужно:

- сериализовать исходящие операции одного validator wallet
- после отправки дождаться подтверждённого увеличения wallet `seqno` перед следующей операцией
- не выполнять `reap` в том же тике, в котором была отправлена election entry
- считать участие успешным только после проверки записи валидатора в Elector, а не только после успешного `sendMessage`
- повторять election entry, если runtime содержит локальную запись, но Elector не подтверждает участие
- добавить интеграционный тест для одновременных `auto_participate` и `auto_reap`, проверяющий появление следующего validator set в `config 36`
