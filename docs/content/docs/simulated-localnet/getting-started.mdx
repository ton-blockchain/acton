---
title: "Getting Started"
description: "Start Acton local development node, use faucet, and run a minimal local workflow"
---

The `acton simulated-localnet` command starts a fast local environment with TON-compatible
blocks, LiteAPI, TonCenter v2/v3, Streaming API, and Emulate API. It is Acton's custom
simplified implementation, not a real TON network or validator cluster.

## Start the Node

```bash
acton simulated-localnet start
```

By default, the node listens on port `5411` (or `[localnet].port` from `Acton.toml`).

You can verify that the server is running:

```bash
curl -s "http://127.0.0.1:5411/api/v2/getMasterchainInfo"
```

## Explore Blocks

Open `http://127.0.0.1:5411/explorer/blocks` to inspect the latest
transactions, masterchain blocks, workchain blocks, and block details in the
local dashboard.

The same block metadata is available through the TonCenter v3-compatible
`GET /api/v3/blocks` endpoint. It supports filtering by `workchain`, `shard`,
`seqno`, `root_hash`, `file_hash`, `mc_seqno`, generated time, logical time,
`limit`, `offset`, and `sort`.

## Fund an Address

Use the built-in faucet command:

```bash
acton simulated-localnet airdrop UQA_ftKIJsHEAE_UgtFOUK15hPzycZooFuUr8duyY9T3kwwM
```

Set a custom amount:

```bash
acton simulated-localnet airdrop UQA_ftKIJsHEAE_UgtFOUK15hPzycZooFuUr8duyY9T3kwwM --amount 50
```

## Use a Custom Port

```bash
acton simulated-localnet start --port 3010
```

Then target the same port for CLI helpers:

```bash
acton simulated-localnet airdrop UQA_ftKIJsHEAE_UgtFOUK15hPzycZooFuUr8duyY9T3kwwM --port 3010
```

## Mine Blocks Manually

Use `--no-mining` when you want full control over block production:

```bash
acton simulated-localnet start --no-mining
```

Accepted messages stay queued until you mine blocks:

```bash
acton simulated-localnet mine
acton simulated-localnet mine 5
```

You can also store the mode in `Acton.toml`:

```acton-toml title="Acton.toml"
[localnet]
no-mining = true
```

## Control Time

Localnet uses a virtual clock for block and transaction timestamps. Move it
forward without waiting for wall-clock time:

```bash
acton simulated-localnet increase-time 3600
acton simulated-localnet mine
```

Set the current virtual Unix time:

```bash
acton simulated-localnet set-time 1710000000
```

Set a one-shot timestamp for only the next mined block:

```bash
acton simulated-localnet set-next-block-timestamp 1710000600
acton simulated-localnet mine
```

The requested timestamp cannot be lower than the latest mined block time.
`acton simulated-localnet status` reports the current virtual time, offset, and any
pending next-block timestamp.

## Simulate API Latency

Use `--response-delay-ms` when you need local API requests to behave more like
a slower remote provider:

```bash
acton simulated-localnet start --response-delay-ms 300
```

This delays `/api/v2`, `/api/v3`, and `/api/emulate/v1` responses. Streaming
subscriptions, control endpoints, and the explorer UI are not delayed.

You can change the delay while the node is running:

```bash
curl -s -X POST "http://127.0.0.1:5411/acton_setNetworkConditions" \
  -H "content-type: application/json" \
  -d '{"response_delay_ms":300}'
```

Use `{"response_delay_ms":0}` to disable the delay. The current value is
included in `/acton_nodeInfo`.

You can also store the same default in `Acton.toml`:

```acton-toml title="Acton.toml"
[localnet]
response-delay-ms = 300
```

## Stop the Node

Press `Ctrl+C` in the terminal where the node is running.

<Callout type="info">
If you use `--dump-state`, the state file is saved during graceful shutdown.
</Callout>
