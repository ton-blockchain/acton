title: "Acton simulated localnet"
description: "Use Acton's simplified TON simulation with compatible blocks and APIs for local development"
---

`acton simulated-localnet` is a fast, deterministic TON development environment for local
execution, forked-state workflows, and faucet-based funding. It produces TON-compatible
basechain and masterchain block cells and exposes compatible LiteAPI, TonCenter v2,
TonCenter v3, Streaming API, and Emulate API surfaces.

This covers a large part of contract and dApp development. The environment is Acton's custom
simplified implementation, **not a real TON network or validator cluster**. It does not model
validators, consensus, shard elections, or the full production node and indexer stack. Use a
Full localnet when the behavior under test depends on those parts of TON.

## Why use it

- Fast local feedback loop for deploys, transactions, and get-method calls.
- Optional fork mode for querying real blockchain state from testnet or mainnet.
- Built-in faucet and startup wallet bootstrap for zero-friction local testing.
- Reproducible environments with SQLite persistence, JSON state files, or checkpoints.
- Runtime network-condition controls for simulating slower API responses.

## Built-in explorer UI

The local node serves a bundled explorer UI from the same HTTP server as the API.

- The root path serves the explorer UI, and client-side routes such as `/explorer`, `/tokens`, `/nfts`, `/explorer/address/<ADDR>`, and `/explorer/tx/<HASH>` all resolve through the same single-page app shell.
- The UI reads blockchain data from `/api/v2` and `/api/v3`, and uses `/acton_getAddressName` plus `/acton_getCompilerAbi` for local alias and ABI lookups.
- Account pages subscribe to `/api/streaming/v2/sse` so new transactions and account state changes appear without waiting for a polling interval.
