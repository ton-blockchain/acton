---
title: "Forking from Network"
description: "Run local node with testnet/mainnet state, including historical block forks"
---

Fork mode lets the local node resolve account state from a remote network while keeping execution local.

Acton pins one masterchain block and uses its state and network configuration as
the local chain origin. An explicit historical fork also uses the selected
block's Unix time.

## Basic Forking

```bash
# Fork from testnet
acton localnet start --fork-net testnet

# Fork from mainnet
acton localnet start --fork-net mainnet
```

## Historical Fork at a Specific Block

```bash
acton localnet start --fork-net testnet --fork-block-number 55000000
```

This is useful for deterministic debugging of historical behavior.

If you omit `--fork-block-number`, Acton resolves the latest masterchain block
once during startup and starts the virtual clock from the current system Unix
time without requesting the block header. If you provide it, account reads, the
network configuration, and the virtual clock all use that exact block. New local
blocks start from the selected block's Unix time.

Acton stores masterchain snapshots for 24 hours under
`build/cache/masterchain-snapshots/<network>/<seqno>.json`. An explicit block
can start from a fresh cache entry without another network request. A latest
fork still queries the network for the latest sequence number before it checks
the matching cache entry. Use `--clear-cache` to remove these entries.

## API Key

Use the TonCenter env var that matches the forked network:

```bash
TONCENTER_TESTNET_API_KEY=YOUR_API_KEY acton localnet start --fork-net testnet
TONCENTER_MAINNET_API_KEY=YOUR_API_KEY acton localnet start --fork-net mainnet
```

Acton reads these env vars automatically for the built-in `testnet` and
`mainnet` fork backends.

## Configure Defaults in `Acton.toml`

```acton-toml title="Acton.toml"
[localnet]
fork-net = "testnet"
fork-block-number = 55000000
```

Now `acton localnet start` automatically uses these defaults.
