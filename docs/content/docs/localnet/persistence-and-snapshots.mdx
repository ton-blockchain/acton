---
title: "Persistence, State Files, and Checkpoints"
description: "Persist local node state with SQLite, portable JSON state files, or in-memory checkpoints"
---

The local node supports three state workflows:

- Persistent SQLite database (`--db-path` or `[localnet].db-path`)
- Portable JSON state files (`localnet state`, `--load-state`, or `--dump-state`)
- Named in-memory checkpoints (`localnet checkpoint`)

JSON state files are direct exports of local node state. They are intended for
the same Acton version that produced them.

## Persistent SQLite State

Use a database file when you want state continuity across runs:

```bash
acton localnet start --db-path .acton/localnet.db
```

To make persistence the project default, configure the same path in
`Acton.toml`:

```acton-toml title="Acton.toml"
[localnet]
db-path = ".acton/localnet.db"
```

Configured relative paths resolve from the project root. `--db-path` overrides
the configured value for a single run; a relative CLI path resolves from the
current working directory.

SQLite preserves committed blocks, transactions, messages, account history,
latest account state and blockchain config, CAS data, compiler ABIs, and
verified sources. Account keys include the workchain, so basechain and
masterchain addresses cannot collide.

Queued but unmined messages, pending time overrides, address aliases, and
derived token/NFT caches belong to the running process. Use a JSON state file
or checkpoint when those runtime details must be carried over exactly.

## JSON State Files

Dump or load the state of a running localnet directly:

```bash
acton localnet state dump states/localnet.json
acton localnet state load states/localnet.json
```

`state load` replaces the current live state and clears all in-memory
checkpoints. The CLI reads and writes the file itself; the localnet server only
receives the JSON bytes. State and checkpoint imports validate their block
history, CAS hashes, config, account references, transactions, messages, and
queue references before replacing live or SQLite state.

State and checkpoint exports are written through a temporary file in the same
directory and atomically moved into place, so a failed write does not truncate
an existing export.

You can also load state during startup:

Load state before startup:

```bash
acton localnet start --load-state snapshots/localnet.json
```

Dump state on graceful shutdown:

```bash
acton localnet start --dump-state snapshots/localnet.json
```

You can combine both to evolve a portable local chain state file between sessions:

```bash
acton localnet start \
  --load-state snapshots/localnet.json \
  --dump-state snapshots/localnet.json
```

<Callout>
  `--load-state` cannot be used when a database path comes from either `--db-path` or
  `[localnet].db-path`.
</Callout>

## Checkpoints

Checkpoints are fast, named restore points kept in the running localnet process:

```bash
acton localnet checkpoint create before-upgrade
acton localnet checkpoint list
acton localnet checkpoint restore before-upgrade
acton localnet checkpoint delete before-upgrade
acton localnet checkpoint clear
```

Restoring a checkpoint is non-destructive: the checkpoint and checkpoints made
after it remain available. Checkpoints disappear when the localnet process
stops unless you export them:

```bash
acton localnet checkpoint export before-upgrade --out states/before-upgrade.json
acton localnet checkpoint import states/before-upgrade.json --name before-upgrade
```

## What a JSON State File Contains

A JSON state file stores enough local node state to resume the same local chain
view later. The state document includes:

- global chain state such as head seqno, logical time, queue policy, and config hash
- latest account state cache
- block history and account deltas by seqno
- transaction and message history indexes
- address aliases managed through `/acton_getAddressName` and `/acton_setAddressName`
- cached token and NFT metadata
- registered compiler ABIs from `/acton_registerCompilerAbis`
- CAS entries for serialized cells and message/code payloads
- pending internal/external message pools

This is broader than just account balances or contract storage. A restored
state file can also bring back explorer-oriented metadata and local admin state.

## Compatibility Notes

- state files are not backward-compatible across schema changes
- JSON state files and SQLite persistence are separate workflows; `--load-state`
  cannot be combined with a database path from either CLI or `Acton.toml`
- when you use `--dump-state`, the state file is written on graceful shutdown

## Choosing a Strategy

| Use case                               | Recommended mode           |
| -------------------------------------- | -------------------------- |
| Stable long-lived local environment    | `--db-path`                |
| Portable, shareable local state        | `localnet state dump/load` |
| Repeated restore points in one process | `localnet checkpoint`      |
| Fast ad-hoc experimentation            | in-memory (no flags)       |
