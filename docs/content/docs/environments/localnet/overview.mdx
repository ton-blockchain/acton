<AvailabilityBadge since="Acton 1.2" />

A localnet runs TON `validator-engine` nodes and TON Center v2/v3 services in Docker. It includes consensus and validator elections. Use it for tests that depend on validator, full-node, or indexer behavior without relying on testnet availability.

## Requirements and startup

### Prerequisites

- [Acton](/docs/installation) 1.2 or later installed.
- An [Acton project](/docs/projects#create-or-initialize-a-project) containing `Acton.toml`.
- For startup accounts, [configured project wallets](/docs/wallets#create-a-wallet).
- A running [Docker engine](https://docs.docker.com/engine/install/) with [Compose v2](https://docs.docker.com/compose/install/). Note that [Docker Desktop](https://docs.docker.com/desktop/setup/install/) includes both.

### Verify Docker availability

Check that the engine and Compose are available:

```bash
docker info
docker compose version
```

### Startup and storage

A full node can take about 20 seconds to start with images already available. Image downloads, additional nodes, and indexer initialization can make startup take longer, including several minutes on a first launch. Wait for node, API, and indexer readiness before sending requests.

<Callout type="caution">
  Insufficient Docker disk space can interrupt localnet operation. Each node can use up to about 9.3 GiB per day.

  Allocate space for all nodes, indexers, snapshot archives, and temporary restore data before startup.
</Callout>

## Configure genesis

<AvailabilityBadge since="trunk" />

Create a network from a separate `genesis.toml` file:

```toml
global_id = -42
simplex_target_rate_ms = 500

[storage]
cell_price = 1000
```

```bash
acton localnet create dev --genesis genesis.toml
acton localnet start dev --detach
```

Missing fields use local development defaults. Acton validates the file and saves the resolved configuration with the network. The source file is only read during creation.

In Studio, select **Localnet** in **Create environment** and open **Genesis configuration**. Import or export `genesis.toml`, edit the fields, or reset to defaults. The configuration covers balances, validators, elections, consensus, fees, sharding, block limits, and configuration voting.

Follow the [custom genesis guide](/docs/environments/how-to/create-network#use-a-custom-genesis) for CLI and Studio instructions. See the [genesis reference](/docs/commands/localnet#genesis-configuration) for field groups, units, and constraints.

## Timing and API conditions

The [`--block-time-ms` option](/docs/commands/localnet#acton-localnet-start) sets an initial block-time target when creating a localnet. Actual timing depends on consensus and resources.

A localnet has no virtual clock, manual mining, or synthetic API rate-limit and response-delay controls. Use simulator [time controls](/docs/environments/simulator/time) or [API conditions](/docs/environments/simulator/network-conditions) for those scenarios.
