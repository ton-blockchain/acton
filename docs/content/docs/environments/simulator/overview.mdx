A simulator network is Acton's simplified TON implementation, also called simulated localnet. It produces TON-compatible basechain and masterchain blocks without validators or consensus. Acton is the only required runtime; Studio can create a simulator without a project when no project wallets are selected.

## Create and connect

[Create a network](/docs/environments/create-network) and [connect clients](/docs/environments/connect) through Studio or the standalone CLI. A standalone simulator serves its bundled explorer at the printed HTTP address, such as `http://127.0.0.1:5411/`.

The [persistence guide](/docs/environments/snapshots#retain-simulator-checkpoints) covers databases and checkpoints for standalone simulators.

## Simulator controls

- [Fork public state](/docs/environments/fork-and-import) and [fund accounts or mint jettons](/docs/environments/fund-accounts).
- [Control time and mining](/docs/environments/simulator/time) for time-dependent scenarios.

- [Save checkpoints](/docs/environments/snapshots) and [change blockchain configuration](/docs/environments/change-config).
- Edit account state through the [control API](/docs/environments/simulator/control-api).

## Compatibility and limits

The simulator exposes TON Center v2/v3, Streaming, Emulate, and optional LiteAPI endpoints. The [HTTP coverage matrices](/docs/environments/simulator/api-compatibility) and [LiteAPI reference](/docs/environments/simulator/liteapi) document their limits.

Message simulation in <kbd>Transaction emulator</kbd> previews execution without committing it. Sending a message to the simulator network changes its local blockchain.

The simulator does not model validator elections, consensus, or shard split/merge behavior. Use a [localnet](/docs/environments/localnet/overview) for tests that depend on validator or indexer infrastructure.
