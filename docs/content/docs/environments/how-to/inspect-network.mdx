Trace transactions, inspect API traffic, and diagnose readiness problems in the selected environment.

## Prerequisites

- A [virtual environment](/docs/environments/how-to/create-network). Status and diagnostics remain available when it is stopped or fails to start.

## Inspect execution and readiness

<Tabs items={["UI", "Simulator CLI", "Localnet CLI"]}>
<Tab value="UI">

Send requests and deployments through the [Studio connection settings](/docs/environments/how-to/connect) to capture them in <kbd>API calls</kbd> and the automatic contract registry.

1. Open <kbd>Explorer</kbd>, find an account, and inspect balances, code, storage, and transaction history. Browse blocks, jettons, and non-fungible tokens (NFTs); save useful addresses in <kbd>Favorites</kbd>.
1. Open a transaction to inspect phases, fees, messages, and state changes. Retrace it for execution details when matching source artifacts are available.
1. Use <kbd>Contracts</kbd> for registered addresses, source artifacts, and application binary interfaces (ABIs). Add existing addresses manually when their deployment did not pass through Studio. Review the <kbd>Sources</kbd> and <kbd>ABI</kbd> catalogs for available metadata.
1. Open <kbd>API calls</kbd> to inspect request/response data, timing, and errors. Enable the <kbd>Studio requests</kbd> filter to include calls made by the UI itself.

![Studio API calls with filters, responses, and timings](../../imgs/api-calls-dark.png)

- For localnet, open <kbd>Network</kbd> → <kbd>Health</kbd> for API readiness, indexer lag, and service health. Inspect <kbd>Nodes</kbd>, <kbd>Validators</kbd>, and <kbd>Stats</kbd> for synchronization, elections, and queues. On startup failure, expand <kbd>Diagnostic details</kbd> for the runtime error. The nodes page includes <kbd>Collector diagnostics</kbd> for observer failures.
- The simulator has no equivalent validator or service log dashboard.

The [common Studio tools](/docs/studio#common-tools) provide message previews, cell inspection, address conversion, and interactive API requests.

</Tab>
<Tab value="Simulator CLI">

```bash
acton simulator status --port 5411 --json
curl --fail http://127.0.0.1:5411/api/v2/getMasterchainInfo
```

Inspect the foreground terminal for process diagnostics. A successful `status` exit code can report `running: false`; inspect the JSON field. For pending messages, check manual mining and the virtual clock.

</Tab>
<Tab value="Localnet CLI">

```bash
acton localnet status dev --json
acton localnet logs dev --tail 200
```

The log command prints a bounded tail of the network operation log once and exits. It does not follow a live stream. Use the reported Dashboard URL for node health and elections. For a pending operation, replace `<OPERATION_ID>` with its ID from status:

```bash
acton localnet operation '<OPERATION_ID>' --network dev --wait
```

An accepted operation is not a completed operation. Inspect its terminal status and error before using the result.

</Tab>
</Tabs>

## Verify the diagnosis

| Symptom | Check |
| ------- | ----- |
| No simulator transactions | Manually mine pending blocks; check the client's selected endpoint. |
| The localnet produces blocks but reads fail | Wait for APIs and indexer readiness, then inspect service health and logs. |
| A deployment or request is missing in Studio | Direct provider/runtime URLs bypass Studio's proxy. |
| Source is unavailable | Build the project version matching the deployed code hash. |
| HTTP `401` from simulator APIs | Supply the token from [`--require-auth`](/docs/commands/localnet#subcommands) through the UI key control or `ACTON_LOCALNET_AUTH_TOKEN`. |
| Old API calls disappear | The bounded request log is temporary and clears on Studio restart. |

Preserve relevant errors and exclude credentials when reporting failures. Use Studio snapshot controls to recover previous states.
