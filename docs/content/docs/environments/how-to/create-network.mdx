<AvailabilityBadge since="Acton 1.2" />

Create an isolated network for scripts and application integration tests.

## Prerequisites

- [Acton](/docs/installation) 1.2 or later installed.
- An [Acton project](/docs/projects#create-or-initialize-a-project) containing `Acton.toml`.
- For startup accounts, [configure project wallets](/docs/wallets#create-a-wallet). The CLI examples use `deployer`.
- For localnet, a running Docker engine with [Compose v2](https://docs.docker.com/compose/install/), as specified in the [localnet requirements](/docs/environments/localnet/overview#requirements-and-startup).

## Create the network

<Tabs items={["UI", "Simulator CLI", "Localnet CLI"]}>
<Tab value="UI">

Start Studio from the project root:

```bash
acton studio
```

1. Open <kbd>Virtual environments</kbd> → <kbd>Create environment</kbd>.
1. Select <kbd>Simulator</kbd> or <kbd>Localnet</kbd> and enter a name.
1. For a simulator, keep <kbd>Clean network</kbd> or choose a public-network fork.
1. Select project wallets under <kbd>Startup accounts</kbd>, or clear the selection for no startup wallets.
1. Select <kbd>Create environment</kbd> and wait for readiness. Open the resulting environment.

Studio preselects [`[localnet].accounts`](/docs/acton-toml#localnet), but initializes only the wallets submitted in the form. Each selected wallet starts with 100 GRAM.

![Studio environment creation and startup account selection](../../imgs/create-environment-dark.png)

</Tab>
<Tab value="Simulator CLI">

Start a persistent network on port `5411`:

```bash
acton simulator start --port 5411 --db-path .acton/simulator.sqlite --accounts deployer
```

The `deployer` must be a configured wallet. Omit [`--accounts`](/docs/commands/simulator#acton-simulator-start) to use `[localnet].accounts`, or pass `--accounts ""` to select none. Keep this terminal open.

In another terminal, inspect readiness:

```bash
acton simulator status --port 5411 --json
```

[Configure defaults](/docs/acton-toml#localnet) in `Acton.toml`; explicit flags override them.

</Tab>
<Tab value="Localnet CLI">

Create a named network and leave it running in the background:

```bash
acton localnet start dev --port-base 19000 --accounts deployer --detach
acton localnet status dev --json
```

The command waits for readiness and prints endpoint URLs.

<Callout type="note">
  Without [`--detach`](/docs/commands/localnet#acton-localnet-start), a newly launched service stays in the foreground and <kbd>Ctrl</kbd>+<kbd>C</kbd> would stop it.
</Callout>

The `deployer` must be a configured wallet. Omit [`--accounts`](/docs/commands/simulator#acton-simulator-start) to use `[localnet].accounts`, or pass `--accounts ""` for no project wallets.

The port range `19000`–`19005` must be free. Omit [`--port-base`](/docs/commands/localnet#acton-localnet-start) to let Acton choose a range.

These options apply to new networks. [Resume an existing network](/docs/environments/how-to/manage-lifecycle#stop-or-resume-work) without creation options.

</Tab>
</Tabs>

## Use a custom genesis

<AvailabilityBadge since="trunk" />

A localnet genesis defines the initial account balances and network rules. You can change validator stakes, election timing, consensus, fees, sharding, block limits, and configuration voting.

Create a separate `genesis.toml` file with the values you need. This example sets a network identifier and a 500 ms block target:

```toml
global_id = -42
simplex_target_rate_ms = 500
```

Missing fields use local development defaults. You do not need to copy the complete configuration into your file.

<Tabs items={["Studio", "CLI"]}>
<Tab value="Studio">

In **Create environment**, select **Localnet**. Open **Genesis configuration** before you create the network.

- **Import genesis.toml** loads your file into the form.
- The field groups let you edit individual values without a file.
- **Export genesis.toml** saves the complete configuration, including defaults.
- **Reset defaults** restores the local development configuration.

Studio highlights invalid values and related fields with an explanation. For example, **Elections start offset** must be less than **Validator round duration**. Correct the highlighted values before you create the network.

</Tab>
<Tab value="CLI">

Pass the file when you start a new network:

```bash
acton localnet start custom --genesis genesis.toml --detach
```

To save the configuration without starting Docker, use `acton localnet create custom --genesis genesis.toml` instead.

The `ACTON_LOCALNET_GENESIS` environment variable can also supply the file path. An explicit `--genesis` path takes precedence. Acton does not automatically load `genesis.toml` from the project directory.

Explicit `--block-time-ms` and `--election-time-seconds` values override the corresponding genesis timing values. Acton checks the configuration before it starts Docker.

</Tab>
</Tabs>

Acton saves the complete configuration with the network. Later changes to the source file do not affect that network. To use a different genesis, create a new network.

To resume a saved network, omit creation flags such as `--genesis`. If you set `ACTON_LOCALNET_GENESIS` in your shell, unset it before you resume the network.

Balances and stakes use whole GRAM. Other fields can use nanograms, seconds, milliseconds, or scaled prices. See the [genesis reference](/docs/commands/localnet#genesis-configuration) for field groups, units, and constraints.

<Accordions>
<Accordion title="Editor completion for genesis.toml">

Export the JSON Schema next to your `genesis.toml` file:

```bash
acton meta get-schema genesis-toml > genesis.schema.json
```

For editors that support TOML schema directives, add this line at the top of `genesis.toml`:

```toml
#:schema ./genesis.schema.json
```

The schema provides field descriptions, defaults, and type checks. Partial tables are supported. Acton also checks relationships between values before creation.

</Accordion>
</Accordions>

## Verify and continue

- In the Studio, confirm the environment is running and open <kbd>Home</kbd>.
- From the CLI, confirm `running: true` for the simulator or `status: "running"` for localnet.

Next, [connect scripts and applications](/docs/environments/how-to/connect) using the reported URLs.
