Managed environments expose configuration and lifecycle controls through the settings icon at the
bottom of the environment sidebar. Both Simulated and Full localnet have a **Snapshots** page
for returning the environment to a known state.

## Full localnet snapshots

Open **Snapshots** and select **Create snapshot**. Enter a name that describes the scenario, then confirm creation.

The table records:

- snapshot name
- creation time
- masterchain block at creation
- compressed archive size
- uncompressed network state size

Snapshot creation stops a running Full localnet while Docker state is archived, then starts it again.
The progress panel separates the operation into prepare, stop network, create archive, and start
network phases, then shows Docker Compose, TON node, API, and indexer readiness.

You can leave the page while the operation runs. Studio continues it in the background and shows the
same progress when you return.

### Restore a snapshot

Select the restore action in the snapshot row and confirm. Restore replaces the current Full localnet
state with the archive, restarts network services, and rebuilds the index before the environment is
available again.

Do not send requests while restore is running. Wait until the TON node, API, and indexer all show
that they are ready.

### Delete a snapshot

Select the delete action in the row and confirm. This removes the saved archive, not the current
running state.

Snapshots can be large. Delete snapshots that are no longer needed and keep enough disk space for
both the compressed archive and working state during creation or restore.

## Simulated localnet snapshots

Open **Snapshots** to create a named snapshot of accounts, block and transaction history,
registered metadata, pending messages, and virtual time. Each snapshot is a JSON file
that survives node and Studio restarts. Creation and restore keep a running node online.

Use **Import snapshot** to add a saved JSON file without changing the environment.
The download action exports the selected saved snapshot. Restore is a separate action.

The inventory remains available when the environment is stopped. A snapshot made while
stopped contains the persisted chain state; capture a running node to include pending
messages and virtual time. Restoring a stopped environment starts it.

## General settings

Open the settings icon for a managed environment. **General** contains:

- editable environment name
- immutable environment ID used by Studio routes and proxy endpoints

Renaming changes labels throughout Studio but keeps the environment ID and endpoint identity.

## Network settings

The **Network** section shows the environment type, network identity, supported endpoint URLs, and
type-specific creation data.

For a Simulated localnet it also shows:

- assigned runtime port
- clean or forked initial state and selected block
- current response delay and rate limit

For a Full localnet it shows the validator count and the V2, V3, Admin, and Config endpoints that are
available.

When the runtime supports network controls, set **Response delay** to emulate a slower API. Use `0`
to disable the delay. The rate limit is shown for reference; create a new environment when the
scenario needs a different startup rate configuration.

## Mining settings

Mining settings appear only for a running Simulated localnet:

- whether automatic mining is enabled
- automatic block time
- whether empty blocks are created

Toggle **Mine empty blocks** when time and block progression must continue without pending messages.
Manual mining and the initial automatic-mining choice are selected when creating the environment.

## Delete an environment

The **Danger zone** is available for managed environments even when the runtime is stopped or failed.
Select **Delete environment**, read the confirmation, and confirm deletion.

Deletion removes the environment metadata and all Studio-managed saved data. For a Full localnet,
this includes its Docker state and snapshots. This action cannot be undone. Do not delete the
environment if you still need its state or snapshots.

Testnet and Mainnet do not have settings or a danger zone because Studio does not own those networks.
