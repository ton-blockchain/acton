## Synopsis

`acton disasm` [_options_] [_boc-file_]

## Description

Disassemble compiled TVM bytecode from a file, a literal BoC string, or a live
contract address.

This command is useful for debugging compiler output, inspecting deployed code,
following library references, and correlating bytecode with Tolk source via
source maps.

## Blockchain Lookups

When `--address` is used, Acton fetches code from the selected network.

- `--net` accepts `mainnet`, `testnet`, `localnet`, and `custom:<name>`
- `localnet` and `custom:<name>` use URLs from `Acton.toml`
- Without `--net`, Acton tries mainnet first and then testnet
- with `--address`, `--follow-libraries` reuses the network that returned the
  contract code

When `--follow-libraries` is used with a local file or `--string`, Acton uses
the explicit `--net` if provided; otherwise library fetches default to
testnet.

## TON Center API Keys

Built-in `mainnet`/`testnet` requests read `TONCENTER_MAINNET_API_KEY` or
`TONCENTER_TESTNET_API_KEY`, depending on the selected network.

For `custom:<name>`, Acton reads `<NORMALIZED_NAME>_API_KEY`. Custom network
names are uppercased and non-alphanumeric characters are replaced with `_`, so
`custom:mock-remote` becomes `MOCK_REMOTE_API_KEY`.

Acton loads `.env` automatically, so the simplest setup during project work is
usually to keep these keys there and use shell environment variables only for
one-off overrides or CI.

## Input Precedence

- `BOC_FILE` and `--string` are mutually exclusive
- `--address` is used only when neither a file nor `--string` is provided
- `--follow-libraries` only replaces the input when the initial disassembly is
  exactly one top-level exotic library-reference cell and the lookup succeeds
- ordinary code, mixed instruction streams, or nested library references are a
  no-op for `--follow-libraries`
- if library lookup fails, Acton warns and disassembles the original code
  instead; this still exits successfully

## Source Maps

If you compiled a contract with `acton compile --source-map`, you can pass that
source map JSON here to annotate the disassembly with original Tolk locations.

`--source-map` only affects annotations in the output. It does not change which
BoC is disassembled.

## JSON Output

With `--json`, Acton prints pretty-printed JSON to stdout.

- `success`: `true` for successful disassembly
- `assembly`: plain disassembly text without inline source-map comments
- `blocks`: source-to-assembly mappings derived from `--source-map`

Each item in `blocks` contains a `source` location and `assembly_ranges`.
`assembly_ranges` stores inclusive zero-based `start_line`/`end_line` pairs
into the `assembly` string.

For BoC input, `blocks` is empty without `--source-map`.
Tolk source input includes mappings from its inspection compilation automatically.

If `--output` is also provided, the output file contains the same plain
`assembly` text while stdout remains JSON.

<AvailabilityBadge since="trunk" />

With `--function`, the response also includes a `functions` array in the requested
order. Each item contains `name`, `method_id`, `assembly`, `blocks`, and `gas_estimate`.
The per-function `assembly` contains only that function's instructions.
Its `blocks` use line offsets into that function's `assembly`; top-level `blocks`
use offsets into the combined `assembly`, including function headers.
Source locations refer to the original files, before annotation overrides.
Identical bytecode may share a cell whose source marks were retained for only one
function. Functions without matching marks have empty `blocks`; Acton does not
attribute another function's source locations to them.

`gas_estimate` contains:

- `value`: sum of the lowest listed opcode costs from the bundled TVM specification
- `has_dynamic_cost`: costs depend on runtime data or include a formula
- `has_control_flow`: the body contains control flow or nested continuations
- `unknown_instructions`: instructions whose cost could not be included

The estimate counts each instruction and nested continuation once. It does not
predict the path taken through branches or the number of loop iterations.
It excludes callees, implicit returns, dispatcher overhead, stack-copy charges,
and additional data-dependent fees. It is neither a lower nor an upper bound on
runtime gas. Use execution profiling when inputs and actual gas costs matter.

For example, `fun increment(value: int): int { return value + 1; }` has this entry:

```json
{
  "name": "increment",
  "method_id": 262143,
  "assembly": "INC\n",
  "blocks": [
    {
      "source": {"file": "example.tolk", "line": 1, "column": 41, "end_line": 1, "end_column": 50},
      "assembly_ranges": [{"start_line": 0, "end_line": 0}]
    }
  ],
  "gas_estimate": {
    "value": 18,
    "has_dynamic_cost": false,
    "has_control_flow": false,
    "unknown_instructions": 0
  }
}
```

Generated method IDs are local to the inspection build. Identify functions by
`name` when matching results to an editor document.

## Exit Status

- `0`: Disassembly completed successfully, including runs with unresolved
  library references that were left as warnings.
- `1`: BoC input was invalid, a blockchain fetch failed, source-map loading
  failed, or the output file could not be written.

## Examples

<AvailabilityBadge since="trunk" />

Disassemble selected functions from a Tolk entrypoint:

```bash
acton disasm contracts/jetton-wallet.tolk --function transfer --function get_wallet_data
```

1. Disassemble a local BoC file:

   ```bash
   acton disasm contract.boc
   ```

2. Disassemble a literal BoC string:

   ```bash
   acton disasm --string "b5ee9c72010104...0840f01c700f2f4"
   ```

3. Disassemble code from a blockchain address:

   ```bash
   acton disasm --address UQA_ftKIJsHEAE_UgtFOUK15hPzycZooFuUr8duyY9T3kwwM --net testnet
   ```

4. Show hashes, offsets, and source locations:

   ```bash
   acton disasm contract.boc --show-hashes --show-offsets --source-map contract.json
   ```

5. Inspect deployed code together with hashes:

   ```bash
   acton disasm --address UQA_ftKIJsHEAE_UgtFOUK15hPzycZooFuUr8duyY9T3kwwM --show-hashes \
                                                                           --net testnet
   ```

6. Write disassembly to a nested output path:

   ```bash
   acton disasm contract.boc --output build/disasm/contract.tasm
   ```

7. Resolve a top-level library-reference cell using a configured custom network:

   ```bash
   acton disasm library-ref.boc --follow-libraries --net custom:staging
   ```

8. Print machine-readable JSON with source-map ranges:

   ```bash
   acton disasm contract.boc --source-map contract.json --json
   ```
